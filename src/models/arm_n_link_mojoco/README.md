# `arm_n_link_mojoco` — structured port-Hamiltonian learning on MuJoCo data

Self-contained copy of the `ph_nn_ode` pipeline, retargeted from our own
analytic simulator to **MuJoCo**. Nothing under `src/models/arm_n_link/` is
imported or modified; every file this package needs lives here.

---

## 1. Why this package exists

The models in `src/models/arm_n_link/` were trained on data generated by
`envs/arm_nlink_so3/arm_nlink_physics.py` — *our own* closed-form port-Hamiltonian
equations, integrated by *our own* Lie–Heun scheme. That invites one obvious
objection:

> You generated the data with the same equations you then fitted. Of course the
> structured model recovers the parameters — the truth is in your hypothesis
> class by construction, and the model can even reproduce your discretisation
> error.

Retargeting to MuJoCo removes that objection. MuJoCo is an independent,
widely-trusted rigid-body engine written by other people, using a different
formulation (relative coordinates, articulated-body algorithm) and a different
integrator (RK4). If the structured model still recovers $m,\ell,c,\mathbb I,d,\Gamma$
from MuJoCo trajectories, the result is about the *method*, not about a shared
implementation.

**Be honest about what this buys.** With `armature = frictionloss = 0` MuJoCo is
simulating the same mechanical system our closed forms describe, so this is a
*validation* — it does not test new physics. That is exactly why there is a
second, misspecified configuration (§8).

## 3. The environment

### 3.1 Ball joints, not hinges — the one non-negotiable choice

The model carries a **full rotation per link**:

$$q = \big(R_1,\dots,R_n\big)\in SO(3)^n,\qquad \omega\in\mathbb R^{3n}$$

That is $3n$ degrees of freedom — one **spherical** joint per link. A standard
2-link arm (`reacher`, `acrobot`, any real manipulator) has $n$ hinge joints and
$n$ DOF. Handing that to this model fails structurally, not statistically:

* **Identifiability collapses.** $M(q)$ is $3n\times3n$ but hinge data only
  excites an $n$-dimensional subspace. The remaining $3n-n$ directions are never
  probed, so the learner may put anything there and the loss cannot object.
* **The rollout leaves the manifold.** `lie_heun_ode_step_nlink` carries no
  constraint forces, so it immediately predicts out-of-plane motion the hinge
  arm physically cannot perform.

So the MJCF uses `<joint type="ball"/>`, giving `nq = 4n` (a quaternion per
joint) and `nv = 3n`. Test **T1** asserts exactly this.

> **Caveat.** A ball-joint chain is a legitimate rigid-body system but it is not
> a real robot arm. Supporting revolute joints means reduced coordinates
> $M_{\text{red}}(\theta) = A^\top T^{-\top} M\,T^{-1}A$ with
> $A=\mathrm{blkdiag}(a_i)$ — a substantially larger change, deliberately out of
> scope here.

### 3.2 Capsule inertia, and why $r$ is a conditioning knob

`arm_nlink_physics.uniform_chain_params` uses
$\mathbb I_i = \mathrm{diag}(0,0,\text{scale}\cdot mL^2)$ — **two zero principal
moments**. MuJoCo rejects that as non-physical, so links here are solid capsules
of radius $r$ about the body $z$-axis:

$$\mathbb I_{zz} = \tfrac12 m r^2,\qquad
  \mathbb I_{xx} = \mathbb I_{yy} = \tfrac1{12}m(3r^2+L^2)$$

The axial direction is the *light* one, so

$$\operatorname{cond}(M)\;\approx\;\frac{\mathbb I_{xx} + m\lVert c\rVert^2}{\mathbb I_{zz}}
  = \frac{\tfrac1{12}(3r^2+L^2)+\tfrac14L^2}{\tfrac12 r^2}\;\xrightarrow[r\to0]{}\;\infty$$

This is the same failure the analytic docstring warns about — *a point mass on
its own axis has no inertia about that axis* — cured with real geometry instead
of a hand-set `inertia_scale`. At $L=1$, $r=0.05$ gives $\operatorname{cond}\approx270$;
the default $r=0.3$ gives $\approx 10$ (measured: `cond(M) = 38.8` including the
$q$-dependent translational term).

**Consequence:** the MuJoCo arm is *not* parameter-identical to the analytic
datasets. Results here are a fresh baseline, not comparable run-for-run with
`arm_n_link/ph_nn_ode/data/`.

### 3.3 Ground truth flows *out* of MuJoCo

We never hand-write $\mathbb I$. The MJCF declares geometry and mass; MuJoCo's
compiler derives the inertial properties; `params_from_mjmodel` reads them back:

| our field | `mjModel` source | note |
|---|---|---|
| `m[i]` | `body_mass` | |
| `c[i]` | `body_ipos` | COM in body frame |
| `I_body[i]` | `body_inertia`, `body_iquat` | $\mathbb I = Q\,\mathrm{diag}(\cdot)\,Q^\top$ |
| `ell[i]` | `body_pos` of the child | 0 for the last link |
| `d[i]` | `dof_damping` | isotropic per joint (checked) |
| `gain[i]` | `actuator_gear` | the diagonal of $\Gamma$ |
| `g` | `opt.gravity` | $-g_z$ |

so the analytic `ArmParams` is a *consequence* of the MuJoCo model, not a
parallel copy that can drift. The dataset carries it in
`settings['arm_params']`, and `train_common.load_data` returns it — calling
`uniform_chain_params` would hand every diagnostic the wrong arm.

### 3.4 Actuation

Three `<motor>` per ball joint, geared along $e_x,e_y,e_z$ and scaled by
$\gamma$, so control $u_i$ delivers joint torque $\mathrm{diag}(\gamma_i)u_i$.
MuJoCo applies the reaction to the parent automatically — that is the
$-R_i^\top R_{i+1}u_{i+1}$ term in $g(q)=T(q)^\top\Gamma$, **Newton's third law,
not a second control**.

## 4. Coordinates — where this goes wrong quietly

MuJoCo's generalized coordinates are **relative**; ours are **absolute**. They
are linked by the joint-rate map already in the codebase:

$$\Omega = T(q)\,\omega,\qquad T_{ii}=I_3,\quad T_{i,i-1}=-R_i^\top R_{i-1},
  \qquad \det T = 1$$

Velocities transform with $T$, so **forces transform with $T^{-\top}$** (power is
invariant) and the mass matrix transforms **congruently**:

$$\boxed{\;M_{\text{rel}} = T^{-\top}M_{\text{abs}}T^{-1},\qquad
        \tau_{\text{rel}} = T^{-\top}\tau_{\text{abs}}\;}$$

Every algebraic gate test is this identity applied to one term. `data.M` (was
`qM`) is in relative coordinates and comparing it to $M_\theta$ directly is the
fastest way to convince yourself a correct model is broken.

### 4.1 Two convention traps found while building this

**(a) `mj_objectVelocity` reports in the *inertial* frame, not the body frame.**
MuJoCo picked `body_iquat = (0,1,0,0)` for these capsules — a $\pi$ rotation
about $x$, i.e. $Q=\mathrm{diag}(1,-1,-1)$. Skipping the correction flips the
sign of $\omega_y,\omega_z$, which leaves $\lVert\omega\rVert$, the kinetic
energy and every rotationally symmetric diagnostic **unchanged** — it would not
surface until the learned model quietly failed. The degeneracy
$\mathbb I=\mathrm{diag}(a,a,b)$ hides it from the parameter extraction too,
since $Q\,\mathrm{diag}(a,a,b)\,Q^\top=\mathrm{diag}(a,a,b)$.

The arbiter is finite differences of `xmat`, $\hat\omega = \mathrm{vee}(R^\top\dot R)$:

```
omega finite-difference  = [-0.351867  -0.632711  -0.311637  ...]
omega qvel recursion     = [-0.351867  -0.632711  -0.311637  ...]   |Δ| = 4e-7  ✓
omega mj_objectVelocity  = [-0.351867  +0.632711  +0.311637  ...]   |Δ| = 2.3   ✗
```

`body_rates()` therefore uses the recursion $\omega_i=\Omega_i+R_i^\top R_{i-1}\omega_{i-1}$,
and `body_rates_mujoco()` applies $Q$ before agreeing with it.

**(b) MuJoCo ≥ 3.11 renamed `data.qM` → `data.M` and reordered `mj_fullM`** from
`(m, dst, qM)` to `(m, d, dst)`. Both are handled.

## 5. The gate — `mujoco_env/test_mujoco_matches_gt.py`

Nothing downstream means anything until this passes. Run it first:

```bash
python mujoco_env/test_mujoco_matches_gt.py --n 2
```

| | test | tolerance |
|---|---|---|
| T1 | ball joints: $n_v=3n$, $n_q=4n$ | exact |
| T2 | $(R,\omega)$ round-trips through MuJoCo losslessly | 1e-12 |
| T3 | $\omega$ agrees three ways (recursion, `mj_objectVelocity`, finite differences) | 1e-7 / 1e-5 |
| T4 | $M$: `data.M` $= T^{-\top}M_{\text{abs}}T^{-1}$ | 1e-10 |
| T5 | gravity: `qfrc_bias`$\big|_{\Omega=0} = -T^{-\top}\mathcal T(V)$ | 1e-10 |
| T6 | damping: `qfrc_passive` $= -T^{-\top}D\omega = -\mathrm{diag}(d)\Omega$ | 1e-10 |
| T7 | actuation: `qfrc_actuator` $= T^{-\top}g(q)u = \Gamma u$ | 1e-10 |
| T8 | the full flow: Lie–Heun $\to$ MuJoCo as $h\to0$ | order $\approx2$ |

**Measured (n = 2):** T1–T7 all pass at $\le 6\times10^{-16}$ — machine
precision. Gate passes for $n = 2, 3, 4$.

T8 is a **convergence study, not an equality**, and the distinction matters.
MuJoCo runs RK4 at $10^{-3}$ while Lie–Heun is 2nd order, so the two agree only
in the limit; asserting a fixed tolerance would test the integrator, not the
physics. Measured:

```
substeps      h        |dR|_inf     |dw|_inf     ratio
      10  0.00500   2.667e-05    9.290e-04       —
      20  0.00250   6.429e-06    2.186e-04     4.25
      40  0.00125   1.612e-06    5.306e-05     4.12
      80  0.00063   4.368e-07    1.309e-05     4.05
     160  0.00031   1.463e-07    3.266e-06     4.01
     320  0.00016   7.417e-08    8.314e-07     3.93
```

Ratio $\to 4$ per halving is exactly $\varepsilon\propto h^2$. **If the two
vector fields differed by any $\delta$, the error would plateau at $\sim\delta T$
and the ratio would collapse towards 1.** No plateau down to $8\times10^{-7}$
therefore bounds the discrepancy below that — a far stronger statement than any
single-tolerance check.

## 6. The model

Unchanged from `arm_n_link`. State $(q,p)$ internally, $(q,\omega)$ externally,
converted by $p=M_\theta(q)\omega$ at step boundaries
(`lie_integrator_nlink._to_p`). **Nothing observable involves the true mass
matrix**, so building the dataset leaks no ground-truth parameter.

$$H(q,p)=\tfrac12 p^\top M^{-1}(q)p + V(q),\qquad
\dot p_i = p_i\times\xi_i + \mathcal T_i(H) - (D\xi)_i + (g(q)u)_i$$

### 6.1 exp1 — black-box (`--subnet_kind nn`)

Four independent networks emit the **whole matrix**: $M^{-1}(q)$ (via a PSD
factor), $D(q)$, $g(q)$, $V(q)$. No kinematic structure. The port-Hamiltonian
*form* is imposed; the operators are free.

### 6.2 exp2 — structured (`--subnet_kind structured --nn_core --structured_potential --share_mass_potential --gravity 9.81`)

The networks emit **physical sub-components**, which are then plugged into the
closed forms:

$$M_{jk} = \mathbb I_j\delta_{jk} - \sum_i m_i[u_{ij}]_\times R_j^\top R_k[u_{ik}]_\times,
\qquad D = T^\top\mathrm{blkdiag}(d_iI_3)T,\qquad g = T^\top\Gamma$$

$$V(q) = g\sum_j\Big[R_j\big(\mu_j^{>}\ell_j + m_jc_j\big)\Big]_z,
\qquad \mu_j^{>}=\sum_{i>j}m_i$$

| predicted | count ($n{=}2$) | used by |
|---|---|---|
| $\log m_i$ | 2 | $M$, $V$ |
| $\mathbb I_i$ (full $3\times3$) | 18 | $M$ |
| $\ell_i$ (free links only) | 3 | $M$, $V$ |
| $c_i$ | 6 | $M$, $V$ |
| $d_i$ | 2 | $D$ |
| $\gamma_i$ | 6 | $g$ |
| $g$ (gravity) | **0** — fixed at 9.81 | $V$ |

`--share_mass_potential` is what makes $M$ and $V$ read the *same* $(m,\ell,c)$
rather than estimating them twice. That single change inverted the earlier
analytic result (~700× improvement): $M$ is **quadratic** in the levers so it
cannot fix their sign, while $V$ is **linear** and can — estimated separately
they disagreed by 120% with inconsistent signs.

`--nn_core` adds a zero-initialised MLP residual on the core vector, so the
model starts *exactly* at the closed form and can only depart from it if the
data demands. Ablation on analytic data showed removing it made things **8×
worse**, not better: the base and the residual co-adapt.

### 6.3 Gauge freedoms — MuJoCo does not fix these

Identifiability is a property of the model class, not the data source. All of
these survive:

* **pH scale gauge** $(M,V,D,g)\to\beta(\cdot)$ with $p\to\beta p$
* **lever gauge** $(\ell,c)\to\lambda(\ell,c)$, $\mathbb I\to\lambda^2\mathbb I$, $g\to\lambda g$
* **mass gauge** $m\to\mu m$, $\mathbb I\to\mu\mathbb I$
* **global lever sign flip**

Fixing $g=9.81$ kills the lever gauge; `--anchor_trace` pins the pH scale gauge
by renormalising $\operatorname{tr}M_{\text{raw}}$ to a constant. Note
$\operatorname{tr}M$ is **$q$-independent**:

$$\operatorname{tr}M = \sum_j\Big[\operatorname{tr}\mathbb I_j + 2\sum_{i\ge j}m_i\lVert u_{ij}\rVert^2\Big]$$

verified numerically at $3.8426666666666662$ with spread $9\times10^{-16}$ across
random $q$. **Anchor at that value, not the default $4n=8$** — otherwise the
learned constants come out scaled by $8/3.8427 = 2.08$ and only match after
gauge correction.

### 6.4 The inertia floor must sit below the truth (`--i_epsilon`)

`structured_subnets.py:526` builds the inertia as

$$\mathbb I = LL^\top + \varepsilon_{\mathbb I}I_3,\qquad \varepsilon_{\mathbb I}=0.05\ \text{(default)}$$

Because $LL^\top\succeq0$, **every eigenvalue of $\mathbb I$ is floored at
$\varepsilon_{\mathbb I}$**. The floor exists to keep $M$ positive definite at
initialisation, and 0.05 was harmless for the analytic arm, whose axial inertia
is $mL^2 = 1$.

The MuJoCo capsule has $\mathbb I_{zz} = 0.0424 < 0.05$. **The floor sits above
the truth**, so the structured model cannot represent the arm it is being asked
to identify.

Strictly, `--anchor_trace` provides an escape: the anchor rescales $M$ by
$\alpha = \text{anchor}/\operatorname{tr}M_{\text{raw}}$, so the model can
inflate $\operatorname{tr}M_{\text{raw}}$ until $\alpha\varepsilon_{\mathbb I}$
drops below the target (here $\alpha\lesssim0.85$ suffices). But that forces the
run into one particular gauge and leaves the *raw* constants ~1.25× off truth
for no reason. Far cleaner to move the floor:

```bash
--i_epsilon 0.002      # ~20x below the true I_zz = 0.0424
```

Cost: nothing — the true $M$ has minimum eigenvalue 0.0424 and
$\operatorname{cond}(M)=38.8$, so positive-definiteness was never at risk.

This is worth flagging generally: **a regulariser tuned to one parameter regime
becomes a hard constraint in another**, and it fails silently — exp2 would
simply have looked worse, and the natural (wrong) reading would be "structure
doesn't transfer to MuJoCo."

`--d_epsilon` and `--m_epsilon` are the same shape of knob for $d_i$ and $m_i$;
the MuJoCo values ($d=0.5$, $m=1$) clear their defaults, so only $\mathbb I$
needed moving.

## 7. The integrator floor — the subtlety unique to MuJoCo data

Against the analytic env, `N_SUBSTEPS` had to *match the generator*: the data
came from the same Lie–Heun scheme at the same $h$, so a perfect model could
reproduce it exactly, discretisation error included.

MuJoCo uses RK4. There is nothing to match — both merely approximate the same
continuous flow, and their difference is an **irreducible error floor**. From
the T8 table:

| substeps | $h$ | $\lvert\Delta\omega\rvert$ | floor on $\lVert d\omega\rVert^2$ |
|---|---|---|---|
| 10 | 0.0050 | 9.3e-4 | ~9e-7 |
| **20** | **0.0025** | **2.2e-4** | **~5e-8** |
| 40 | 0.0013 | 5.3e-5 | ~3e-9 |

For scale, the structured model reaches $\lVert d\omega\rVert^2\approx2\times10^{-5}$
on analytic data. **At 10 substeps the floor is within an order of magnitude of
that**, so the model would be limited by *our integrator* rather than its own
capacity — and "structured did worse on MuJoCo" would be an artefact of the
experimental setup, not a finding. The default here is therefore **20**
(floor ~400× below the signal, 2× the compute); override with `--n_substeps`.

## 8. Matched vs misspecified

**Matched** (`armature = frictionloss = 0`, contacts disabled): MuJoCo simulates
exactly the system our closed forms describe. Tests that the pipeline recovers
truth from an independent implementation.

**Misspecified**: two knobs put the truth *outside* the structured model class.

* `--armature α` adds $\alpha I$ to the **joint-space** diagonal, i.e.
  $T^\top\alpha T$ in absolute coordinates. That is **not** of the form
  $\mathrm{blkdiag}(\mathbb I_i)+\sum_i m_iJ_{v,i}^\top J_{v,i}$ — no `ArmParams`
  represents it.
* `--frictionloss f` adds **Coulomb** friction, non-smooth, whereas $D$ is
  linear viscous.

`SHARED_SPEC_KEYS` in the report includes both, so runs trained on different
physics cannot be silently compared against one ground truth.

Also unsupported, and **raised rather than ignored**: `varying_friction`,
`air_drag`, `wind_force_std`, `external_force_std`. A dataset that quietly
dropped the wind term would train against the wrong physics and merely look
"worse".

## 9. Running it

```bash
# 0. the gate — always first
python mujoco_env/test_mujoco_matches_gt.py --n 2

# 1. dataset (matched)
python data_gen/mujoco_arm_datagen.py --n 2 --samples 64 --timesteps 30 \
       --random_u_scale 2.0

# 2. exp1 — black-box whole-matrix
cd ph_nn_ode && python train.py --n 2 --loss mse --relative_inputs \
       --anchor_trace 3.8426666666666662 --total_steps 10000 \
       --samples 64 --timesteps 30 --random_u --random_u_scale 2.0 \
       --g_diag 0.5 0.7 0.5 --friction_coeff 0.5

# 3. exp2 — structured sub-components
python train.py <same flags> --subnet_kind structured --nn_core \
       --structured_potential --share_mass_potential --gravity 9.81

# 4. report (GT trace comes from MuJoCo)
python make_comparison_pdf.py --run_dir data/<exp1> data/<exp2> \
       --out data/comparison_report.pdf

# 5. misspecified variant
python data_gen/mujoco_arm_datagen.py --n 2 --armature 0.1 --frictionloss 0.05
```

The dataset filename encodes the full spec, so matched and misspecified runs
cannot collide.
